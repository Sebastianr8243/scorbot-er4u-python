# Report index

The dictionary of work on this project. One row per report, newest first. Look a change up here, open the report, and follow its links to the spec, log and tests. The current state of every capability is on [`../STATUS.md`](../STATUS.md).

**Rules**
- One report per piece of work that changes behaviour, evidence, a requirement or a hazard. Typos and formatting do not get one.
- IDs are `R-NNNN`, in order, never reused. A file is `R-NNNN-short-slug.md` in this folder; copy [`TEMPLATE.md`](TEMPLATE.md).
- A report is not edited after the fact except to fix a mistake or to say it is superseded. New findings get a new report with `Supersedes`.
- Evidence levels (E0 to E5) are defined in [`../STATUS.md`](../STATUS.md). A report states the level it reached, never the level it hopes for.
- Add the row here and update `STATUS.md` in the same commit as the report.
- The reports sit beside [`../project/PROJECT_LOG.md`](../project/PROJECT_LOG.md), they do not replace it: the log keeps the older story, reports hold new work in a fixed shape. Before 2026-10-13 the log is the record.
