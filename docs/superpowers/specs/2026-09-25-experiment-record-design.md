# Experiment record and replay: design

**Status:** Draft for review
**Date:** 2026-09-25
**Implements:** System design §5.4, requirements R-06, R-07 (schema part), R-09; GitHub work item 2
**Branch:** `feat/experiment-record` from `main`. No USB code, no dependency on PR #1.

## 1. Purpose

Give every experiment one local, append-only record of what was commanded,
what the controller and camera reported, and what the operator decided, so a
run can be replayed and inspected with no robot attached. This is the
foundation the simulated backend and camera adapter will write into.

**Success:** a synthetic session written by the recorder is read back by the
replay tool, reproduces the same ordered event timeline, reports integrity
problems explicitly, and shows at a glance whether the data is real,
simulated, or synthetic. All tests run offline under `unittest`.

## 2. Non-goals

- No change to `openScorbot/`, `scorbot/robot.py`, or `scorbot/state.py`.
- No simulated backend, camera capture, OpenCV, or VLM code (later slices).
- No LeRobot export, plots, CSV export, or cross-run comparison yet.
- `examples/record_raw_state.py` is left as is; porting it is a follow-up.
- No new runtime dependencies. Standard library only, Python ≥ 3.10.

## 3. Session layout

```
<root>/<session_id>/
  metadata.json   # written on open, rewritten atomically on close
  events.jsonl    # one JSON object per line, append-only
  frames/         # image files referenced by frame events (created on demand)
  notes.md        # blank operator observation form, filled by hand
```

`session_id` = `YYYYMMDDTHHMMSSZ-<6 hex>`. The directory is created
exclusively; an existing session is never overwritten.

## 4. Metadata (`metadata.json`)

| Field | Meaning |
|---|---|
| `schema_version` | `1` |
| `session_id` | as above |
| `data_source` | **required**: `"real"`, `"simulated"`, or `"synthetic"` |
| `robot_id`, `controller_id` | operator labels, e.g. `lab-er4u-1` |
| `operator`, `task`, `start_pose_note` | free text; `start_pose_note` defaults to `"unmeasured"` |
| `camera_ids` | list, may be empty |
| `calibration` | `{"path", "sha256"}` or `null` |
| `code` | `{"git_commit", "git_dirty", "source_fingerprint"}`; the fingerprint is a SHA-256 over `scorbot/` and `openScorbot/` `.py` files so it works outside git |
| `environment` | Python version, platform, `pyusb`/`numpy` versions if installed, `usb_driver` operator label |
| `started_utc`, `started_monotonic_ns` | set on open |
| `ended_utc`, `event_count`, `closed_cleanly` | set on close; absent after a crash |

## 5. Events (`events.jsonl`)

Every line has the same envelope:

```json
{"seq": 12, "type": "state", "source": "robot", "logged_monotonic_ns": 130,
 "observed_monotonic_ns": 123, "utc": "…", "payload": {…}}
```

- `seq` starts at 0 and increases by 1 with no gaps.
- There are two timestamps, both taken from the recording process's
  `time.monotonic_ns()` clock:
  - `logged_monotonic_ns` is taken by the recorder, inside the write lock,
    when the event is written. It never decreases, and it is the one the
    integrity check applies to.
  - `observed_monotonic_ns` is optional. The source supplies it for when
    the observation happened: the camera's capture time, or the time the
    USB packet was received. `log_state` fills it in from
    `state.host_monotonic_ns` when that field exists (PR #1). Streams are
    aligned on this timestamp, falling back to `logged_monotonic_ns`, and it
    has no ordering check. A frame captured before a state can legitimately
    be logged after it.
- `utc` is for humans only.
- Values are strict JSON: NaN and Infinity are rejected when written.

| `type` | Required payload keys | Notes |
|---|---|---|
| `state` | `encoder_counts`, `home_switch_bits`, `connected` | Accepts a `RobotState` or a dict and stores `asdict()` unchanged, so PR #1's extra fields (`packet_index`, `signed_encoder_counts`, …) pass through. Optional `raw_packet_hex` keeps the undecoded controller bytes so later decoders can be checked against them (§5.4). `main`'s API does not expose raw packets yet, but the field is already in the schema. |
| `command` | `command_id`, `kind`, `params` | `command_id` is generated by the recorder |
| `command_result` | `command_id`, `status` | `status` ∈ `completed`, `faulted`, `timeout`, `rejected`; optional `completion_source`, `detail` |
| `frame` | `camera_id`, `frame_number`, `path`, `width`, `height` | `path` is relative to the session and must exist when logged; optional `camera_config_id`, `mount_id` |
| `detection` | `camera_id`, `frame_number`, `label`, `bbox_xyxy`, `confidence`, `model_id` | optional `operator_correction` |
| `decision` | `choice` | operator decision; optional `refers_to_seq`, `reason` |
| `fault` | `message` | optional `command_id` |
| `note` | `text` | |

The writer rejects unknown types and missing required keys. The reader keeps
events of unknown types and lists them in the integrity report, so an older
reader still opens newer files.

## 6. Components

**`scorbot/session/record.py`: `SessionWriter`**

```python
with SessionWriter.create(root, data_source="synthetic", robot_id="lab-er4u-1", ...) as rec:
    rec.log_state(state)
    cid = rec.log_command("jog_joint", {"joint": "base", "delta_counts": 50})
    rec.log_command_result(cid, "completed", completion_source="encoder_delta")
    rec.log_frame("cam0", 0, path="frames/000000.png", width=640, height=480)
```

- A lock covers assigning `seq` and writing the line, so camera and robot
  threads can share one writer.
- Each line is flushed as it is written. `close()` calls fsync on the file
  and rewrites `metadata.json` through a temp file plus `os.replace`.
- Writing after `close()` raises an error.

**`scorbot/session/replay.py`: `load_session(path) -> Session`**

`Session` holds `metadata`, `events` (a list of dicts), and `report`.
`report` is a list of findings, each marked `error` or `warning`:

- `error`: a gap or duplicate in `seq`; `logged_monotonic_ns` going backwards;
  an unparsable line that is not the last one; `data_source` missing.
- `warning`: a truncated final line, which is dropped and reported; the
  session was never closed; a frame file is missing; a command has no
  result; an unknown event type.

It also has one helper: `nearest(events, t_ns, type="state")` returns the
closest event, compared on `observed_monotonic_ns` (falling back to
`logged_monotonic_ns`), and its signed time difference. Aligning frames to states
always reports that gap and never implies they happened at the same time.

**`python -m scorbot.session <dir>`: CLI replay**

- Prints a banner with `data_source` in capitals, so REAL, SIMULATED, and
  SYNTHETIC look different at a glance.
- Then the metadata summary, one line per event
  (`+t_ms  seq  type  source  short-summary`), counts per type, and the
  integrity report.
- Exits 1 if there are any errors, otherwise 0.
- `--limit N` caps how many timeline rows are printed.

**`examples/make_synthetic_session.py`**

Writes a session marked `data_source="synthetic"`. It contains:

- idle states;
- one command, its states, and its result;
- two small generated PNG frames (stdlib `zlib` + `struct`, no Pillow);
- a detection, an operator decision, and one fault;
- a note.

It prints the path and then replays it. This is the hardware-free sample
the design doc asks for.

## 7. Testing (`tests/test_session.py`, unittest, temp dirs only)

1. Round trip: write the synthetic session, then load it. The loaded
   events equal what was written, `seq` is 0..N-1, and the report has no
   errors (R-06).
2. `data_source` is required and must be one of the three values. The
   replay banner shows it (R-09).
3. The writer rejects NaN, unknown types, missing keys, a frame path that
   does not exist, and writes after close.
4. Crash tolerance: when the last line is truncated and metadata was never
   closed, the session still loads with warnings, not errors.
5. Corruption: a seq gap or a monotonic time that goes backwards is an
   error, and the CLI exits 1.
6. Concurrency: two threads write 500 events each. The result has 1000
   unique, contiguous `seq` values, every line parses, and `load_session`
   reports zero errors.
7. `nearest()` returns the correct event and the signed time difference.
   It prefers `observed_monotonic_ns`, and when observed times are out of
   order it produces no error.
8. `RobotState` from `decode_state()` round-trips through `log_state`.
   `raw_packet_hex` is stored when it is supplied.
9. A fresh subprocess that runs `import scorbot.session` leaves `usb` and
   `openScorbot` absent from `sys.modules`.

Run the tests with `python -m unittest discover -s tests`. Code must stay
compatible with Python 3.10: no `datetime.UTC`, `typing.Self`, or `tomllib`.

## 8. Risks and decisions

- **JSONL, not SQLite or Parquet.** It is readable by hand, append-only,
  and survives crashes. Size is not a concern for supervised runs. A later
  exporter can convert it.
- **`*.jsonl` is gitignored.** The tests generate their sessions and nothing
  binary is committed.
- **Schema versioning.** Any breaking change bumps `schema_version`. The
  reader raises an error on a `schema_version` newer than the one it
  supports.
